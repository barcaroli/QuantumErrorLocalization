* =====================================================================
* CONCORD/SCIA -- Education chain subset + degree-3 test rule
* FH_example benchmark, extended for quantum-computing degree
* impact analysis (IBM/D-Wave/Dirac-3)
*
* Variables (7): ENROLL, EDULEV, DEGREE, DEGLEV, DEGCTY, FIELD (original
* 6, unchanged) + AGE (new).
*
* Rules (13 REGOLE lines): the original 10 (5 logical skip-logic rules)
* + 3 new incompatibility rules:
*   A: AGE(00-14) EDULEV(8,9)          -- degree 2
*   B: AGE(00-14) DEGLEV(1-8)          -- degree 2
*   C: DEGCTY(1) FIELD(5) DEGLEV(4)    -- degree 3, genuinely
*      irreducible (no pair of these 3 conditions alone is implausible;
*      only the joint triple is -- field-of-specialisation code 5 exists
*      only at technical-diploma level in the FH_example education system, but the
*      same field+level combination is plausible if the degree was
*      obtained abroad, DEGCTY=2)
*
* IMPORTANT, VERIFIED INTERACTION: rule B combines with the pre-existing
* V3_nonblank rule (DEGREE!=2 -> DEGLEV filled) to imply "AGE<15 ->
* DEGREE must equal 2 exactly (not blank, not 1)" -- because DEGREE in
* {1,blank} would otherwise require DEGLEV filled (V3_nonblank), which B
* forbids under 15. This is a logically valid consequence, not a bug,
* but it means records like a never-enrolled child (ENROLL=4, DEGREE
* correctly blank per V2) now require touching more fields to become
* fully consistent than in the simpler 6-variable version of this
* example (see TESTDATA_README.txt, record R2). Kept as-is deliberately
* (verified with the project's own resolution engine, no contradiction).
*
* NOTE: ENROLL and AGE are mandatory (no blank) in this subset.
